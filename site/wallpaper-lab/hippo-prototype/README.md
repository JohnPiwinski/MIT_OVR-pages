# Hippo fundamental-domain prototype

Open `output/report.html` in a browser. It compares the scanned source, ten OpenCV component candidates, the selected corrected vector domain, and translated copies. The report links to each candidate SVG, the corrected domain SVG, and numerical analysis.

To regenerate from the saved source crop in Git history:

```
python3 wallpaper-lab/hippo-prototype/extract_hippo.py
```

To use a different **crop of the same hippo figure**:

```
python3 wallpaper-lab/hippo-prototype/extract_hippo.py --input /path/to/hippo-crop.png --output /path/to/output
```

The detection ranges are calibrated to the supplied crop; arbitrary images, scale changes, and full pages are not yet supported. The script requires Python, OpenCV (`cv2`), NumPy, SciPy, and Shapely. Tests: `python3 -m unittest discover -s wallpaper-lab/hippo-prototype -p 'test_*.py' -v`.

OpenCV detects connected white regions. The ranked component is buffered by 1.5 source pixels to approximate the center of the ink. Arc-length resampling and Gaussian smoothing reduce scan noise while preserving sharp corners; the result is still a polyline, not analytic arcs or Bézier curves. Centroid offsets from multiple components estimate two translation vectors. To address scan distortion and line thickness, the script projects the buffered candidate onto a translation cell, resolves overlaps, assigns small unfilled pieces, and lifts the pieces back to the plane. The result is a corrected scan-derived polygon, not a claim that the raw scanned component was an exact tile.

The numeric check measures coverage and interior overlap on the model's translation cell. A separate test checks neighboring cells. The result depends on the measured lattice; it does not establish that the source has no other symmetries. Treating the group as translations only uses the published C1 point-group solution, not an independent classification. Colors in the report distinguish copies; they need not be preserved by translations.

`exercise.html` shows the hippo dissection. `build_exercise.py` uses OpenCV circle detection to locate the rounded lobe, cuts a slightly expanded circular region from the first domain, moves it by a lattice translation, and builds the second domain. Its perimeters differ, establishing noncongruence. `dissection.py` computes intersections with transformed copies of the second domain and validates source/target coverage and lack of overlaps; its affine matrices support reflections and rotations in addition to translations. Run `python3 wallpaper-lab/hippo-prototype/build_exercise.py` to regenerate `exercise-data.js`.

`fleur.html` demonstrates a separate dissection with reflections and rotations. `build_fleur.py` extracts a complete upright fleur-de-lis with OpenCV, smooths its boundary, and uses half of it as the domain candidate. It projects that candidate onto a Dirichlet cell for the estimated D3 group, resolves scan-induced gaps and overlaps, and lifts the corrected pieces back. The corrected domain is close to, but not identical to, the detected half-tile. A source overlay displays the extracted outline and correction. The rotation and reflection were compared with the raster scan; the model and the tile-area estimate are still approximations of that scan. Run `python3 wallpaper-lab/hippo-prototype/build_fleur.py` to regenerate `fleur-data.js`.

`build_brick.py` uses OpenCV to measure an enclosed source brick, idealizes the running-bond pattern, and builds a quarter-brick domain and a second domain related by a half-turn dissection. Its scan symmetries and geometric coverage are tested. Regenerate with `python3 wallpaper-lab/hippo-prototype/build_brick.py`. `build_strips.py` extracts half of a curved strip edge, then completes a domain with mirror and translation symmetry; the scan comparison and geometric coverage are tested. `build_diamond.py` measures the source diamonds and preserves the shaded/unshaded distinction when determining symmetries; its second domain is disconnected but satisfies the tiling checks. `build_circles.py` derives a D4 domain and generates the overlapping-circle pattern from source edges inside it. `build_scales.py` reconstructs the staggered scallops from scan-extracted edges and checks their mirror and oblique translation lattice. `build_zigzag.py` reconstructs source edges from a checked half-turn domain. `build_bands.py` reconstructs wavy bands from a scan-checked mirror/glide group. `assignment.html` also includes eight draft patterns generated by `build_provisional.py`; several now use manually simplified tile artwork, while their group placements and fundamental domains still need review against the source scans.
